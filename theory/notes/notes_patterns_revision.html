01

Hashing

Trade space for near-constant-time lookups.

unordered_mapunordered_set O(1) avg access

Concept

A hash table maps keys to buckets via a hash function, giving average O(1) insert, lookup, and delete. In C++, unordered_map and unordered_set implement this. The core idea in problem-solving: instead of scanning the array again to check "have I seen this value / does its complement exist", store what you've seen in a map as you go, so each lookup is O(1) instead of O(n).

How to recognise

  • Phrases like "have you seen this before", "does a pair/complement exist", "check duplicates".
  • Counting frequencies of elements/characters.
  • Grouping items by some derived key (e.g. sorted string for anagrams).
  • A brute-force nested loop (O(n²)) is checking existence inside the inner loop — that inner check is almost always replaceable with a map.

Common approach

  1. Decide what the key should be (raw value, sorted signature, tuple, prefix sum…).
  2. Decide what the value should store (index, count, list of indices…).
  3. Single pass: for each element, first check the map for what you need, then insert/update the current element (order matters to avoid using an element against itself).
Pitfall: inserting the current element before checking for its complement can cause a value to pair with itself. Also remember unordered_map has no ordering guarantee — if order matters, you still need something else (e.g. an array or map).

Example problem

Two Sum Given an array of integers nums and an integer target, return the indices of the two numbers that add up to target. Assume exactly one solution exists. 
vector<int> twoSum(vector<int>& nums, int target) {
    unordered_map<int,int> seen; // value -> index
    for (int i = 0; i < (int)nums.size(); ++i) {
        int complement = target - nums[i];
        auto it = seen.find(complement);
        if (it != seen.end()) {
            return {it->second, i};
        }
        seen[nums[i]] = i;      // insert AFTER checking
    }
    return {}; // no solution
}
Time O(n)  ·  Space O(n)
02

Two Pointers

Walk two indices toward each other (or together) to cut O(n²) to O(n).

sorted arraysO(n)O(1) extra space

Concept

Instead of comparing every pair (O(n²)), maintain two indices that move through the data structure — often from opposite ends of a sorted array — and use the ordering to decide which pointer to move. Each element is visited a constant number of times, giving linear time.

How to recognise

  • Array is sorted, or can cheaply be sorted, and you need pairs/triplets matching a sum/condition.
  • Palindrome checks (compare from both ends inward).
  • Merging two sorted sequences.
  • In-place removal/compaction of elements (fast/slow pointer variant, same direction).

Common approach

  1. Sort the input if order isn't already guaranteed (adds O(n log n), usually still fine).
  2. Set left = 0, right = n - 1.
  3. Compare nums[left] + nums[right] (or similar) against target: if too small, ++left; if too large, --right; if equal, record and move both, skipping duplicates.
  4. For "triplet" problems: fix one element with an outer loop, two-pointer the rest.

Example problem

3Sum Given an integer array nums, return all unique triplets [a, b, c] such that a + b + c == 0. 
vector<vector<int>> threeSum(vector<int>& nums) {
    sort(nums.begin(), nums.end());
    vector<vector<int>> res;
    int n = nums.size();

    for (int i = 0; i < n - 2; ++i) {
        if (i > 0 && nums[i] == nums[i - 1]) continue; // skip dup anchor
        if (nums[i] > 0) break; // smallest is positive -> no triplet sums to 0

        int lo = i + 1, hi = n - 1;
        while (lo < hi) {
            int sum = nums[i] + nums[lo] + nums[hi];
            if (sum == 0) {
                res.push_back({nums[i], nums[lo], nums[hi]});
                while (lo < hi && nums[lo] == nums[lo + 1]) ++lo;
                while (lo < hi && nums[hi] == nums[hi - 1]) --hi;
                ++lo; --hi;
            } else if (sum < 0) {
                ++lo;
            } else {
                --hi;
            }
        }
    }
    return res;
}
Time O(n²)  ·  Space O(1) extra (excl. output)
03

Sliding Window

Grow and shrink a contiguous window instead of recomputing from scratch.

contiguous subarray/substringO(n)

Concept

Maintain a window [left, right] over an array or string. Expand right to include new elements and update window state incrementally; when the window violates a constraint, shrink from left until it's valid again. Because each pointer only moves forward, total work is linear instead of recomputing the window from scratch for every start position.

How to recognise

  • "Longest / shortest / count of contiguous subarray or substring such that…"
  • Constraint can be checked incrementally as elements enter/leave the window (sum, distinct count, frequency map).
  • Fixed-size window ("every subarray of size k") or variable-size window (expand/shrink based on a condition).

Common approach

  1. Initialise left = 0 and any running state (sum, frequency map, distinct count).
  2. For each right, add s[right] to the state.
  3. While the state violates the constraint, remove s[left] from the state and ++left.
  4. Update the answer using the current window size right - left + 1.
Pitfall: forgetting to update the running state when shrinking the window (e.g. decrementing a frequency count) leads to a window that looks valid but isn't.

Example problem

Longest Substring Without Repeating Characters Given a string s, find the length of the longest substring without repeating characters. 
int lengthOfLongestSubstring(string s) {
    unordered_map<char,int> lastIndex; // char -> last seen index
    int left = 0, best = 0;

    for (int right = 0; right < (int)s.size(); ++right) {
        char c = s[right];
        if (lastIndex.count(c) && lastIndex[c] >= left) {
            left = lastIndex[c] + 1; // jump window start past the repeat
        }
        lastIndex[c] = right;
        best = max(best, right - left + 1);
    }
    return best;
}
Time O(n)  ·  Space O(min(n, alphabet))
04

Binary Search

Halve a monotonic search space every step.

sorted / monotonicO(log n)

Concept

If a search space is sorted, or has a monotonic "yes/no" predicate (everything below some point fails, everything above succeeds — or vice versa), you can discard half the remaining space every iteration. This applies not only to searching sorted arrays, but to binary search on the answer: guess a value, check in O(f(n)) whether it's feasible, and narrow the range.

How to recognise

  • Array is sorted (possibly rotated).
  • Asked for "first/last position such that…", or minimum/maximum value satisfying a condition.
  • A brute-force linear scan works, but the underlying condition is monotonic — a strong hint the answer can be binary-searched even without a sorted array in sight (e.g. minimum capacity, minimum time, square root).

Common approach

  1. Define lo, hi bounding the search space.
  2. Loop while lo <= hi; compute mid = lo + (hi - lo) / 2 (avoids overflow).
  3. Evaluate the condition at mid and shrink to the half that can still contain the answer.
  4. For rotated/complex arrays, first work out which half is "normally sorted", then check if the target lies in that half's range.
Pitfall: off-by-one errors in the loop bound (< vs <=) and in updating lo/hi (mid vs mid ± 1) are the most common bugs — pick a convention and stay consistent.

Example problem

Search in Rotated Sorted Array An ascending array has been rotated at an unknown pivot. Given target, return its index, or -1 if absent, in O(log n). 
int search(vector<int>& nums, int target) {
    int lo = 0, hi = (int)nums.size() - 1;

    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;
        if (nums[mid] == target) return mid;

        if (nums[lo] <= nums[mid]) {          // left half is sorted
            if (nums[lo] <= target && target < nums[mid]) hi = mid - 1;
            else lo = mid + 1;
        } else {                                // right half is sorted
            if (nums[mid] < target && target <= nums[hi]) lo = mid + 1;
            else hi = mid - 1;
        }
    }
    return -1;
}
Time O(log n)  ·  Space O(1)
05

Monotonic Stack

Keep a stack sorted; pop to resolve "next greater/smaller" in amortized O(1).

next greater elementO(n)

Concept

A monotonic stack is kept strictly increasing or strictly decreasing from bottom to top. As you scan the array, whenever the current element breaks the stack's order, you pop elements off — and each pop tells you the answer for that popped element (e.g. "the next greater value is the current one"). Every element is pushed once and popped at most once, giving amortized O(n) despite the nested-looking loop.

How to recognise

  • "Next greater / next smaller element" for every position.
  • "How many days until a warmer temperature" style problems.
  • Histogram / rectangle problems (largest rectangle in histogram, trapping rain water).
  • Any brute force that, for each element, scans forward/backward until a bigger/smaller value is found.

Common approach

  1. Iterate through the array, keeping a stack of indices (not values, so you can compute distances).
  2. While the stack is non-empty and the top's value violates the monotonic property against the current value, pop it and record the answer for that popped index using the current index.
  3. Push the current index.
  4. Anything left on the stack at the end has no answer (e.g. remains 0 / -1).

Example problem

Daily Temperatures Given daily temperatures, return an array where answer[i] is the number of days you'd have to wait after day i for a warmer temperature, or 0 if none exists. 
vector<int> dailyTemperatures(vector<int>& T) {
    int n = T.size();
    vector<int> res(n, 0);
    stack<int> st; // indices, temps decreasing bottom -> top

    for (int i = 0; i < n; ++i) {
        while (!st.empty() && T[st.top()] < T[i]) {
            int idx = st.top(); st.pop();
            res[idx] = i - idx;
        }
        st.push(i);
    }
    return res;
}
Time O(n) amortized  ·  Space O(n)
06

DFS & BFS

Go deep first, or go wide level-by-level.

trees / graphs / gridsO(V + E)

Concept

DFS (depth-first search) explores as far as possible down one branch before backtracking — implemented with recursion or an explicit stack. BFS (breadth-first search) explores level by level using a queue, and is the go-to when you need the shortest path in an unweighted graph, since it discovers nodes in increasing order of distance from the source.

How to recognise

  • Trees, graphs, or 2D grids/matrices (flood fill, islands, maze problems).
  • Connected components / "how many separate groups".
  • Shortest path or minimum number of steps in an unweighted graph → BFS.
  • Explore all paths, or "does a path exist" without needing the shortest one → DFS is usually simpler.
  • Level-order traversal, or "minimum depth" → BFS.

Common approach

  1. DFS: recursive (or stack-based) function that marks the current node visited, then recurses into each unvisited neighbour.
  2. BFS: push the start node into a queue and mark visited; while the queue isn't empty, pop the front, push all unvisited neighbours (marking them visited at push time to avoid duplicates), optionally tracking distance/level.
  3. For grids, neighbours are typically the 4 (or 8) adjacent cells with bounds checking.
Pitfall: in BFS, mark a node visited when you enqueue it, not when you dequeue it — otherwise the same node can be added to the queue multiple times.

Example problem

Number of Islands Given an m x n grid of '1's (land) and '0's (water), return the number of islands (connected groups of land, 4-directionally). 
int numIslands(vector<vector<char>>& grid) {
    if (grid.empty()) return 0;
    int rows = grid.size(), cols = grid[0].size();
    int count = 0;

    function<void(int,int)> dfs = [&](int r, int c) {
        if (r < 0 || r >= rows || c < 0 || c >= cols || grid[r][c] != '1') return;
        grid[r][c] = '0'; // mark visited in place
        dfs(r + 1, c); dfs(r - 1, c);
        dfs(r, c + 1); dfs(r, c - 1);
    };

    for (int r = 0; r < rows; ++r) {
        for (int c = 0; c < cols; ++c) {
            if (grid[r][c] == '1') {
                ++count;
                dfs(r, c);
            }
        }
    }
    return count;
}
// BFS variant: replace dfs(r, c) with a queue<pair<int,int>> that
// pushes the start cell, marks it visited, then pops and pushes
// unvisited '1' neighbours until empty.
Time O(rows × cols)  ·  Space O(rows × cols) (recursion stack / queue)
07

Top K with Heaps

Keep only the k elements you need, not the whole sorted list.

priority_queueO(n log k)

Concept

priority_queue is a binary heap giving O(log k) push/pop and O(1) peek at the top. Rather than sorting the entire input in O(n log n) to find the top k elements, maintain a heap of size k as you scan: O(n log k), which is meaningfully cheaper when k ≪ n.

How to recognise

  • "Kth largest / smallest element", "top k frequent", "k closest points".
  • You only need a bounded number of "best" items, not a full ordering.
  • Streaming / online data where you must maintain top-k as elements arrive.

Common approach

  1. For "top k largest": use a min-heap of size k. Push each element; if size exceeds k, pop the minimum. What remains is the k largest, with the smallest of them on top.
  2. For "top k smallest": use a max-heap the same way (or negate values in a min-heap).
  3. For "top k frequent": first build a frequency map, then heap on (count, value) pairs.
  4. C++ default priority_queue<T> is a max-heap; pass greater<T> as the comparator for a min-heap.

Example problem

Kth Largest Element in an Array Given an integer array nums and integer k, return the k-th largest element (not the k-th distinct one). 
int findKthLargest(vector<int>& nums, int k) {
    priority_queue<int, vector<int>, greater<int>> minHeap; // size stays <= k

    for (int num : nums) {
        minHeap.push(num);
        if ((int)minHeap.size() > k) {
            minHeap.pop(); // discard current smallest
        }
    }
    return minHeap.top(); // smallest of the k largest = the k-th largest
}
Time O(n log k)  ·  Space O(k)
08

Backtracking

Choose, explore, undo — DFS over the space of partial solutions.

permutations / combinationsexponential, pruned

Concept

Backtracking is DFS over a decision tree of partial candidates: at each step you make a choice, recurse to extend the candidate, and then undo the choice ("backtrack") before trying the next option. The key advantage over brute force is pruning — abandoning a branch immediately once it can no longer lead to a valid solution, instead of building it out fully first.

How to recognise

  • "Generate all…", "return all possible…" — permutations, combinations, subsets, partitions.
  • Constraint-satisfaction puzzles: N-Queens, Sudoku, word search on a grid.
  • The answer requires exploring a combinatorial space, but invalid branches can be detected early.

Common approach

  1. Write a recursive function with the current partial solution (often a vector passed by reference, mutated in place) and a "start index" or remaining state.
  2. Base case: partial solution is complete → record a copy of it.
  3. For each candidate choice at this step: if it's invalid/prunable, continue; otherwise add it to the path, recurse, then remove it (pop_back) — this undo step is what makes it "backtracking".
  4. Use a start index to avoid re-generating the same combination in a different order; sort input first if you need to skip duplicates or prune early (e.g. if (candidate > remaining) break;).
Pitfall: forgetting to undo the choice (e.g. missing path.pop_back()) leaves stale state that corrupts every subsequent branch.

Example problem

Combination Sum Given distinct integers candidates and a target, return all unique combinations where the chosen numbers (each usable unlimited times) sum to target. 
void backtrack(vector<int>& candidates, int target, int start,
                vector<int>& path, vector<vector<int>>& res) {
    if (target == 0) {
        res.push_back(path);
        return;
    }
    for (int i = start; i < (int)candidates.size(); ++i) {
        if (candidates[i] > target) break; // pruning (candidates sorted)

        path.push_back(candidates[i]);
        backtrack(candidates, target - candidates[i], i, path, res); // i, not i+1: reuse allowed
        path.pop_back();                                             // undo
    }
}

vector<vector<int>> combinationSum(vector<int>& candidates, int target) {
    sort(candidates.begin(), candidates.end()); // enables the break-based prune
    vector<vector<int>> res;
    vector<int> path;
    backtrack(candidates, target, 0, path, res);
    return res;
}
Time exponential, pruned in practice  ·  Space O(target) recursion depth
09

Dynamic Programming

Solve overlapping subproblems once, reuse the answer everywhere else.

memoizationtabulation

Concept

DP applies when a problem has optimal substructure (the optimal solution is built from optimal solutions to subproblems) and overlapping subproblems (the same subproblem recurs many times in a naive recursion). Instead of recomputing it, store the result once — either top-down (recursion + memoization cache) or bottom-up (iterative table, "tabulation").

How to recognise

  • "Count the number of ways to…", "minimum/maximum cost/profit to…", "can we reach/partition into…".
  • A brute-force recursive solution exists but is exponential because it re-solves identical subproblems.
  • The problem involves making a sequence of decisions (over an array, string, or grid) where each decision's cost/benefit depends on prior decisions.

Common approach

  1. Define the state: what small set of parameters uniquely identifies a subproblem (e.g. "amount remaining", "index in string + index in other string").
  2. Write the recurrence: express the state's answer in terms of smaller states.
  3. Base cases: the smallest subproblems with known answers.
  4. Choose direction: top-down recursion with a memo (easier to derive from the recurrence) or bottom-up table (usually faster, avoids recursion overhead/stack limits).
  5. Optimize space if the recurrence only depends on the last one or two rows/states — collapse the table to O(1) or O(n) instead of O(n²).

Example problem

Coin Change Given coin denominations coins and an amount, return the fewest number of coins needed to make up that amount, or -1 if impossible. 
int coinChange(vector<int>& coins, int amount) {
    // dp[a] = fewest coins to make amount 'a'
    vector<int> dp(amount + 1, amount + 1); // amount+1 acts as "infinity"
    dp[0] = 0;

    for (int a = 1; a <= amount; ++a) {
        for (int c : coins) {
            if (c <= a) {
                dp[a] = min(dp[a], dp[a - c] + 1);
            }
        }
    }
    return dp[amount] > amount ? -1 : dp[amount];
}
Time O(amount × coins)  ·  Space O(amount)
